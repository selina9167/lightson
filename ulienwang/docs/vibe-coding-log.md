## 第一次需求提示

**提示內容摘要**

以生成式 AI 協助建立 Ameba Mini 語音控制 LED 系統。至少支援「左邊開燈（藍燈）」與「右邊開燈（綠燈）」，須顯示辨識與執行狀態、只依板卡回傳顯示實際燈態，並處理非控制語句及通訊失敗。

**AI 建議與產出**

- 選用電腦瀏覽器的 Web Speech API 進行語音辨識。
- 選用 Web Serial 經 USB 傳送白名單指令，不需在程式內保存 Wi-Fi 密碼。
- 板卡每次執行後回傳 `ACK` 與 `STATE`，網頁只依 `STATE` 更新燈態。
- 產生 AMB82-MINI Arduino 韌體、瀏覽器介面、指令解析測試與驗收表。

**查證結果**

- 官方 AMB82-MINI 資料與本機板卡定義皆顯示藍燈為 `LED_B`（D23）、綠燈為 `LED_G`（D24）。
- 官方板卡範例使用 `digitalWrite(..., HIGH)` 開燈、`LOW` 關燈。
- 本機已安裝 `realtek:AmebaPro2 4.1.1-build20260915`。
- 本次建立專案時未偵測到已連接的 COM 埠，因此尚未宣稱實機驗證完成。

## 後續互動紀錄

實機測試與修改時，依時間順序把提示詞、AI 回覆摘要、修改檔案與驗證結果追加在此處。

### CMD 即時監控功能

**使用者提示**

希望增加一個 CMD 畫面，以便觀察程式運作過程。

**AI 修改**

- 新增 `tools/monitor_server.py`，同時提供控制頁與接收事件紀錄。
- 新增 `start_monitor.cmd`，可用雙擊方式啟動監控。
- 網頁事件紀錄同步傳送到本機 CMD；監控程式不開啟 COM3，因此不會和 Web Serial 搶用序列埠。

**實際遇到的問題與修正**

第一次把舊的靜態伺服器切換到監控伺服器時，新程序沒有成功接手 8000 連接埠，瀏覽器因此出現 `ERR_CONNECTION_REFUSED`。先在測試連接埠 8002 驗證網頁回應為 HTTP 200、事件 API 回應為 204，再修正啟動方式並重新啟動 8000。最後重新載入控制頁，畫面出現「控制頁已載入，等待連接 AMB82-MINI」，確認監控版本已生效。

### 改為 Python 主控程式

**使用者提示**

希望整個程式能用 Python 從 CMD 呼叫，方便直接觀看 `print` 資訊。

**設計調整**

- 新增 `voice_controller.py` 作為系統主程式。
- Python 直接開啟 COM3、傳送序列指令、等待 `ACK`、解析 `STATE`，並把完整過程印在 CMD。
- 瀏覽器只負責 Web Speech API 語音辨識及操作畫面，透過本機 HTTP API 把指令交給 Python，不再使用 Web Serial。
- 此設計讓 COM3 只有 Python 一個擁有者，避免瀏覽器與 CMD 同時搶用序列埠。
- 新增 `start_voice_controller.cmd`，可直接雙擊啟動；原有 `start_monitor.cmd` 改為相容入口。

**驗證結果**

- Python 成功開啟 COM3，取得板卡回傳的 `STATE blue=0 green=0`。
- 以不改變原狀的 `LEFT_OFF` 完成端對端測試：Python 送出指令，板卡回傳 `ACK LEFT_OFF`，接著回傳藍燈滅、綠燈滅的狀態。
- Python 協定測試 3 項通過；JavaScript 指令白名單測試 4 項通過。
